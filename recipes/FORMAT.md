# 新实验配方数据格式（供生成器读取）

每个配方文件以 `module.exports = [ ... ];` 导出数组，每个实验用**对象简写字段**表示。字段含义：

```js
{
  id: 'unique_snake_id',          // 唯一英文 id，与实验类型 id 一致
  n: '实验中文名称',
  c: '类别（必须是以下 6 类之一）', // 上游工艺 / 下游工艺 / 分析检测 / 质量控制 / 分子生物学 / 蛋白科学
  s: '一句话简介',
  p: '原理（1-2 句）',
  a: '适用场景（1 句）',
  i: '起始材料（1 句）',
  o: '输出产物（1 句）',
  d: '预计耗时（如 约 3-4 h）',
  y: '参考产量或说明（不适用写 不适用（检测/分析型方法））',
  sp: [ ['质控项', '参考范围', '说明'], ... ],     // 4-6 项
  st: [                                            // 必须 8 步
    ['阶段', '步骤标题', '操作要点（1-2 句）', '这一步的作用（1 句）', '关键参数（如 pH 7.2；4 °C，30 min）', '易错点：后果（1 句）'],
    ... 8 项
  ],
  m: [                                             // 4-5 个指标
    ['key', '指标名称', '单位', 正常下限, 正常上限, 严重下限或 null, 严重上限或 null, '备注'],
    // 枚举指标：下限位置写期望值，上限位置写另一个选项，例如 ['result','结果','','合格','不合格',null,null,'按方法判定']
    ...
  ],
  r: [                                             // 3-4 条诊断规则
    ['rule_id', '问题标题', '问题类别', 'severity', 0.8x, 'low|high|outside|enum|combo', 'metric_key', '原因1;原因2;原因3', '措施1;措施2;措施3'],
    ...
  ],
  optional: ['key1','key2'],                       // 可选指标（非每次必填），可为 []
  g: [                                             // 新增试剂/耗材词条，可为 []
    ['reagent_id','名称','别名1,别名2','类别','作用','主要成分','注意事项','储存条件'],
    ...
  ]
}
```

## 硬性要求

1. `id` 全局唯一，小写下划线命名，不要与现有 21 类重复（见下方已有 id 列表）。
2. `st` 必须正好 8 步，每步 6 个元素齐全；操作要点要具体到可照做，参数要有真实量级（温度、时间、pH、浓度、转速、流速等）。
3. `m` 的 key 在本实验内唯一，使用英文驼峰；阈值须为通用参考值且符合行业常识，不要设置过窄区间；只在有共识的指标上设严重线。
4. `r` 的 metric 必须能在 `m` 中找到；`combo` 类型请写 `combo` 并在 metric 位置写 `指标A+指标B`，生成器会转成组合条件（两个条件均为 low/high，按指标定义方向）。
5. `g` 中试剂名称不要与已有 74 种重复（尤其 PBS、TMB、鲎试剂、无水乙醇、滤膜、Tris 中和缓冲液等）。
6. 内容必须是公开药典 / 行业通用 SOP 层面的知识，用于演示与培训；不要写任何真实产品的注册工艺参数或企业专有配方。
7. 字符串内如需引号请用中文引号或转义，不要破坏 JS 语法。
